Problem Statement & Architectural Objectives

Transitioning from vulnerable app-level logic to database-enforced integrity.

System Vulnerabilities

  • Unmonitored off-hours Data Manipulation Language (DML) queries.
  • Inventory overselling during concurrent multi-item customer checkouts.
  • Audit trail loss when parent transactions suffer explicit rollbacks.

Database Engine Solutions

  • PL/SQL Encapsulation: Atomic order handling via ECOMM_ORDER_PKG.
  • Time-Window Policy: Strict DML operational windows (08:00 - 18:00).
  • Autonomous Logging: Independent PRAGMA AUTONOMOUS_TRANSACTION commits.
💡 Speaker Notes: Traditional client applications fail when direct DB connections occur. We pushed security, validation, and logging directly into the Oracle engine so policies are enforced regardless of the client application.

Autonomous Security Engine (ECOMM_SECURITY_PKG)

Time-window policy enforcement and non-repudiable audit logging.

Policy Execution Flow

  1. DML Trigger intercepts INSERT / UPDATE / DELETE.
  2. Invokes check_dml_window(p_table, p_action).
  3. Evaluates system time against operational hours (08:00–18:00, Mon-Fri).
  4. If non-admin & outside window: Raises ORA-20001 error.
  5. Invokes log_audit_event autonomously.
-- Key Autonomous Transaction Block
PROCEDURE log_audit_event(...) IS
  PRAGMA AUTONOMOUS_TRANSACTION;
BEGIN
  INSERT INTO AUDIT_LOG (...) VALUES (...);
  COMMIT; -- Independent commit!
EXCEPTION
  WHEN OTHERS THEN ROLLBACK; RAISE;
END log_audit_event;
💡 Speaker Notes: PRAGMA AUTONOMOUS_TRANSACTION is crucial. Even if an unauthorized query triggers a rollback, the security denial record is independently committed to AUDIT_LOG.

Transactional Order Processing (ECOMM_ORDER_PKG)

Guaranteeing ACID compliance during complex multi-table checkouts.

Validation & Pricing

Verifies customer existence, product unit price, and verifies stock availability in INVENTORY.

Atomic Mutation

Inserts master record into ORDERS, line items into ORDER_ITEMS, and decrements stock in INVENTORY.

Payment & Receipt

Generates transaction entry in PAYMENTS and returns the new ORDER_ID via OUT parameter.

💡 Speaker Notes: By encapsulating checkout inside ECOMM_ORDER_PKG.place_order, we eliminate partial writes or dirty reads. Stock deductions and order creations either succeed completely or fail gracefully.

Multi-Tiered Database Triggers & Mutating Fix

Active data guarding and solving ORA-04091 mutating-table errors.

Business Rule Triggers

  • • TRG_PRODUCTS_PRICE_CHECK: Rejects negative prices & max 80% single-update price drops.
  • • TRG_PAYMENTS_AMOUNT_CHECK: Enforces positive payment thresholds.
  • • TRG_INVENTORY_NEGATIVE_CHECK: Prevents negative physical inventory.

Compound Trigger Architecture

TRG_INVENTORY_LOW_STOCK_COMPOUND uses a 4-section compound structure:

Buffers low-stock rows during AFTER EACH ROW and commits audit alerts in AFTER STATEMENT, eliminating ORA-04091.

💡 Speaker Notes: Standard row triggers fail with ORA-04091 when querying the table being updated. Our Compound Trigger buffers row changes in a PL/SQL collection and processes the security log after the DML statement finishes.

Power BI Integration & Analytical Views

Decoupled analytical abstraction layer for high-throughput reporting.

VW_BI_SALES_OVERVIEW

Pre-calculates total revenues, customer spend rankings, and monthly sales trends for Power BI charts.

VW_BI_INVENTORY_HEALTH

Flags low-stock thresholds dynamically with REORDER NEEDED status badges.

VW_BI_SECURITY_DENIALS

Exposes denial rates and audit trail metrics for security compliance monitoring.

💡 Speaker Notes: Reporting tools should never run raw aggregation queries directly against production transactional tables. Power BI connects exclusively to optimized database views (VW_BI_*), preventing locks.
